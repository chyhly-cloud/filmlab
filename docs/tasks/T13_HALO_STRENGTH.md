## 2. 可预测性（`tools/eval/t13_flare_index.py`）

- 换算为"截断光源比截断点亮多少档"：黄昏约 +1.5，夜景约 +3.5–4.5，夜间大面积亮窗或立面约 +5.5–6.5。
- 现有亮度先验对这些场景的截断块一律按"灯"处理（名义 +3.5 档）。按面积分类不是原因，我此前的这一判断已更正。
- RAW 中截断块外圈的亮度（数码镜头眩光指数）与所需档数无关：r = +0.13，n = 8。
- 数码曝光时间也不能给出单调关系：4 s 对应 ×4–8，6 s 与 30 s 对应 ×0.25。

## 3. 按最佳强度目视（`t03_sheet.py` 的 `代际@s`；光源局部）

- R1-04-5（×4）、R1-05-6（×8）：窗框的红橙描边与窗户上沿的红色光带出现，与真实扫描相似，这是此前所有版本都没有的。
- R1-00-1（×1）、R1-06-7（×2）：范围与颜色接近真实，R1-06-7 略偏黄白。
- R1-07-8、R1-03-4（×0.25）：剩余的橙色是灯本身的颜色（截断灯芯重建的颜色偏暖且未饱和），不是光晕。

## 结论

光晕的物理（形状与颜色）在给对光源亮度时基本正确。唯一的未知量是每个截断光源比截断点亮多少，单张 RAW 里没有这一信息：
- 包围帧最多短 3 档；
- EXIF 换算的绝对亮度先验几乎总是触到 8 档上限；
- 镜头眩光指数不相关。

这是输入数据的缺口，不是胶片物理的缺口。

## 4. 光源亮度旋钮（物理未知量）与最终对照

截断光源亮度的整体偏移 `rawio.load_raw(..., source_stops=…)`（模块默认 `rawio.SOURCE_STOPS = 0`，逐位不变）同时决定灯芯与光晕强度，是单张 RAW 中真正缺失的量。

逐场景扫描（`MODE=stops`，`t13_source_stops.json`）的最佳偏移：

| 场景 | 最佳偏移 |
|---|---:|
| R1-00-1、R1-02-3 | 0 |
| R1-06-7 | +1 |
| R1-04-5、R1-01-2 | +2 |
| R1-05-6 | ≥ +3 |
| R1-07-8、R1-03-4 | ≤ −2 |

默认 0 位于中间。

最终对照：真实 | next | next_lab_halo | next_lab_halo + 该场景旋钮，见 `docs/figures/t13/halo_lamps_*.jpg`、`halo_full_*.jpg`。
- R1-04-5（+2）、R1-05-6（+3）：窗上沿的红橙光带与窗框红橙描边出现，与真实相似；next 只有一片白雾。
- R1-06-7（+1）、R1-00-1（0）：光晕范围与颜色接近真实。
- R1-01-2（+2）：窗户底边的红晕略重于真实。

### 黄昏两帧（`docs/figures/t13/dusk_brighter.jpg`、`tools/eval/t13_core_density.py`）

- R1-03-4 调亮到 +3 档时，灯带下方出现与真实相同的红橙光晕团，说明这帧的灯确实很亮、光晕物理成立；+6 档过头。
- 灯芯本身在模型里已经是白色（成片 1.0 / 1.0 / 0.99），底片各层在 +3 档时也已接近中性极大曝光的饱和密度。
- 橙色出现在灯芯外 0–100 µm 的过渡区：真实 L* 96–99、b* +4 ~ +18（白），模型 L* 72–92、b* +29 ~ +67（橙）。
  该区在数码 RAW 中未截断，曝光为实测值，约比中灰高 4–5 档；真实冲印店把它印成白色，模型没有。
- 这是"高光多亮才印成纯白"的扫描与印放映射问题，不属于光晕物理；R1-07-8 另有胶片曝光与数码曝光不一致的问题。
