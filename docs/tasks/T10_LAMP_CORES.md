灯芯分场景：
- R1-00-1：0.076 → 0.034；
- R1-07-8：0.201 → 0.172；
- R1-03-4：0.111 → **0.194**；
- R1-04-5：0.016 → 0.021。

原因：next_lab 以固定光号代替逐帧自动定光，也就去掉了逐帧定光里的额外高光肩部（`x_knee` / `x_white`）。灯芯附近能保留暖色，R1-00-1 明显更接近真实；但在 R1-03-4 上变得过红。

**光源局部目视**：近灯区域现在最主要的误差是**灯本身的颜色**。真实扫描中城市灯光（R1-03-4）与窗户（R1-07-8）为白色或偏冷，模型为橙黄。

亮区追踪（`MASK=bright`：亮度 97–99.7 百分位，排除传感器截断；`t10/trace_bright_lab.json`）：
- 多数夜景模型与真实相差在几个单位内，没有系统性偏暖；
- 例外：R1-07-8 真实更蓝（b* −21 对 −9），R1-03-4 模型偏黄（+15.6 对 +4.8）。

因此橙色来自**数码 RAW 已截断的灯芯**：
- 截断之上的真实亮度没有记录，只能由高光重建估计，而估计值偏低；
- 于是三层乳剂没有全部饱和，灯的固有暖色保留下来，再叠加红色光晕；
- 真实胶片则过曝很多档，三层接近饱和，印成白色。

这与此前截断光源亮度的反推工作（`docs/CENSORED_SOURCE_FIELD.md`、`docs/INVERSE_SOURCE_RADIANCE.md`、`docs/EXIF_PRIOR_HOLDOUT.md`）是同一问题，受数据所限。
