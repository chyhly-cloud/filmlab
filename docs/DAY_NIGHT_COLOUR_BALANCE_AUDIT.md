# 日间/蓝调整体色彩：逐帧灰平衡的有界核查

本轮由用户指出日间色差和夜间不够蓝触发。不是新的光晕研究，不用整体增蓝或经验调色补偿。

## 同负片下可隔离的一项原因

复用`base-colour-audit`中两场景的同一无返回曝光诊断负片密度缓存，固定材料、显影、扫描转换、K、s、相纸和肩部，仅删除PrintTiming.M逐通道仿射灰平衡。该M的绿通道恰为off=0、slope=1，因此删除M和全部通道改用原绿通道映射两个控制在这两场景完全等价，不是两份独立证据。不重新拟合定光，不改正式管线。

统计是同一组24px稳定格的**各格模型−真实Lab残差的场景中位数**，不是整图ΔE或真实灰卡。区域采用此前几何远区mask_far_geometric_1500，咖啡馆498格、蓝调795格；严格“返光可忽略”mask没有有效格，不能谎称已观测真实无光晕基底。

|场景/状态|ΔL*|Δa*|Δb*|
|---|---:|---:|---:|
|日间咖啡馆，原灰平衡|−22.96|−10.18|−22.47|
|同负片，撤销逐通道M|−24.42|−16.05|−8.89|
|蓝调道路，原灰平衡|+5.66|−15.98|+18.80|
|同负片，撤销逐通道M|+2.06|−14.71|+5.27|

负Δb是偏蓝、正Δb偏黄；不能把正/负Δa混作蓝色。

这一隔离证明：模型逐帧M能在咖啡馆加强过蓝，同时在蓝调道路削弱蓝色。**不需要改显影，就已能大幅改变用户指出的两种蓝黄误差。**但日间Δa向更绿退步、亮度仍严重不足，夜景也仍偏绿，故直接关闭M不能作为完整修复。不能据此证明真实扫描应该没有自动校色、显影已经准确、或所有场景色差都由M造成。

## 方法边界与回放检查

缓存为先投影的密度，和先扫描再投影不交换。每格原输出回放的Lab最大分量误差，咖啡馆p50/p95/max=0.00783/0.07640/0.70094，蓝调=0.00277/0.01227/0.07083。主诊断预设中位门槛0.1；草地0.11451（p95=3.306）未通过，完全排除本轮M归因，不把其近似扫描结果作为候选。咖啡馆极少数格误差大，结论限定为中位趋势，不能声称逐像素精确复现。

受控灰片另以BB3200、D65、相同光视亮度、现有感光度积分检验每场景引擎内的曝光→q→染料→扫描密度→两种定光输出。每行比较严格保持同负片，但不同场景引擎有原帧物理差异，不把两帧灰片差直接称纯扫描效应。这只是计算见证，非真实800T材料测量。已知D65灰片在两场景引擎中都能输出明显蓝色，因此不能说显影/后端从根本上不能产生蓝；它不认证准确的蓝色幅度或彩色色块响应。

输入光源估计旧审查已显示日间咖啡馆远区日光权重约0.95%，单一D65替换却未统一修复；本轮不重复这项消融，不据最终RGB拟合真实光谱或改感光度。

## 决策

将整体色彩准确性列为独立问题。优先研究逐帧灰平衡怎样区分画面本身的颜色与扫描偏色，并核对输入照明推断；显影的非中性响应仍需独立证据，不提前排除。若提出新自动校色方法，应固定输入负片同时通过日间和蓝调验收，不能靠统一加蓝、暖色滤镜或改变显影常数追照片。
