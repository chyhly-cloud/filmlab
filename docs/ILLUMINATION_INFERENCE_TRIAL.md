# 照明推断与全局类别裁剪的独立复核

承接基础色彩约束，本轮只检验输入推断与计算局部性，不修改材料、显影、扫描或current/next。

## 已有nearest策略并不普遍改善输入

四种已知照明×24块Ohta实测反射率，继续使用理想CIE相机和库存感光度条件积分参考。比较原随机成员、已有nearest_members策略及移除全局类别裁剪；不看真实照片评分选择谱形。

|---|---:|---:|---:|---:|

D65蓝绿比退步，不能因多数值好就普遍采用。固定灰片跨四种背景的D65层曝光跨度由0.347/0.086/0.242变0.206/0.041/0.278EV；BB3200由0.490/0.270/0.626变0.523/0.240/0.482，仍有反向退步。nearest没有解决“将物体色与照明混淆”，不再用实拍最终RGB选择它。

## 找到独立的计算局部性问题

Engine._expose_mixed以某类光源的全图平均软权重小于0.003为由，跳过该类的全部直接与返回源曝光。这是性能近似，不是物理阈值；它没有检查局部权重。

构造**算法反例**：先冻结局部权重，不再做照明估计。同一个4×4区域被分配LED权重1，其余区域为日光，中心RGB固定。32×32画幅中LED均值0.015625，被计算；只扩大无关背景至128×128，均值0.00097656，整类被跳过，中心三层H从[0.53858,1.35509,1.89039]变成[1e−9,1e−9,1e−9]。

这不是实测灯具，也不是这批照片实际发生了几十档误差的证据。它证明的是：**光源分配已经冻结后，数值优化仍能凭无关画幅抹掉局部曝光**。这一点可独立修正。

Eval-only `weighted_responses`保留全部已分配权重，仍用原光谱成员和同一直接/返回响应。上述中心H及返回源在两画幅完全一致；所有类别本来都被保留时，与原方程逐位一致。`unpruned_exposure`先重放原有阈值路径（误差门槛2e−9），再计算未裁剪路径。没有新经验阈值、光源倍率或材料系数。

完整自动推断仍会受背景影响：取消全局裁剪后，BB3200受控灰片最大跨度从0.626降至0.384EV，但没有归零；D65部分层反而略增。不能把局部性修正误称为照明已准确恢复。

## 决策

保留未裁剪计算的独立候选与局部性回归测试，暂不改正式管线。不采用nearest作为整体颜色方案。**本轮得到一个可修复的数值缺陷，但排除了它是这五张照片整体色差主因的解释。**自动照明推断的物体色/光源色不可辨识性依然存在；不能靠扩大颜色方案搜索掩盖，也不能因此反推实际800T感光度。
